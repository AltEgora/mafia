# Эмуляция игры «Мафия» (Задание 1)

Учебный проект на C++20: собственный умный указатель `SharedPtr<T>` и консольная
«Мафия», где каждый игрок действует в своей нити `std::thread` (или, по выбору,
как корутина C++20), а ведущий моделируется программно. Сторонние библиотеки не
используются.

Что реализовано:

- обязательные пункты 1 и 2: `SharedPtr`, игра, нити, ведущий;
- пункт 3: логирование в файлы через `std::filesystem` и концепты для типов игроков;
- пункт 4: режим `--coroutines`, где игроки — корутины C++20 (свои `Task` и
  `promise_type`), и `std::ranges`/`std::views` для работы со списками игроков и голосов;
- пункт 5: три дополнительные роли — журналист, телохранитель и ниндзя; набор
  ролей задаётся YAML-файлом, парсер собственный;
- пункт 6: ИИ-агент (`--ai-agents K`). Днём он обсуждает и голосует через
  бесплатный API языковой модели (по умолчанию OpenRouter, бесплатная Nemotron 3 Super),
  ночью ходит обычным ботом; при недоступности API молча играет ботом.
  Метаданные трека с ИИ — в [docs/AI_TRACK.md](docs/AI_TRACK.md).

## Сборка

Нужны CMake ≥ 3.20 и компилятор с C++20. Проверено на Apple clang 17,
LLVM clang 22 и GCC 14: сборка без предупреждений с `-Wall -Wextra -Wpedantic -Wshadow`.

```bash
cmake -S . -B build
cmake --build build -j
```

ИИ-агентам нужна libcurl: CMake находит её сам (на macOS она есть в SDK).
Без неё проект собирается так же, а агенты всегда играют как обычные боты.
Явно отключить libcurl: `-DMAFIA_WITH_CURL=OFF`.

Тесты (не ходят в сеть — агенты проверяются на моке):

```bash
ctest --test-dir build --output-on-failure
```

Сборка с санитайзерами (`thread`, `address`, `undefined` или `address,undefined`):

```bash
cmake -S . -B build-tsan -DMAFIA_SANITIZER=thread -DCMAKE_BUILD_TYPE=Debug
cmake --build build-tsan -j
ctest --test-dir build-tsan --output-on-failure
```


## Запуск

```bash
./build/mafia --players 10 --interactive --open-announcements --full-log
./build/mafia --players 9 --roles-config configs/extended.yaml --log-dir logs
```

| Параметр | Значение |
|---|---|
| `--players N`, `-n N` | число игроков, N > 4 (до 500) |
| `--interactive` | вы — один из N игроков; иначе играют только боты |
| `--open-announcements` | ведущий раскрывает роль погибшего, кто стрелял и кого спасли |
| `--closed-announcements` | ведущий называет только сторону погибшего: «мирный» или «мафия» (по умолчанию) |
| `--full-log` | полный лог в консоли: раздача ролей, ночные ходы, решения мафии, рассуждения ботов |
| `--roles-config FILE` | набор ролей из YAML-файла (без параметра — классический набор) |
| `--log-dir DIR` | писать логи раундов и итоговую статистику в `DIR/game_<сид>/` |
| `--mafia-k K` | мафии `max(1, floor(N/K))`; K ≥ 3, по умолчанию 3 |
| `--coroutines` | игроки — корутины в нити ведущего, а не отдельные нити (см. ниже) |
| `--ai-agents K` | K ботов заменить ИИ-агентами (см. ниже); бесплатный ключ OpenRouter — `OPENROUTER_API_KEY` |
| `--no-pauses` | без пауз (по умолчанию реплики и голоса идут раз в 0,5 с, ночь длится 2 с, между днём и ночью пауза 1,5 с) |
| `--seed S` | сид генератора: партия повторяется один в один |
| `--help` | справка |

Без `--roles-config` и `--log-dir` вывод программы такой же, как до добавления
новых ролей: это проверено побайтным сравнением 40 партий.

Краткий лог — то, что слышит игрок за столом: объявления ведущего, реплики,
итоги голосований, в конце раскрытие всех ролей. Полный лог добавляет скрытые
действия (строки с префиксом `[лог]`). В интерактивной игре с `--full-log`
скрытые действия печатаются только после окончания партии, чтобы не подсматривать.

### Ввод в интерактивном режиме

Ведущий перед каждым ходом пишет, что требуется, и перечисляет допустимые номера.

- Обсуждение: номер игрока — обвинить его; `0` — заявить «я мирный житель».
- Голосование: номер игрока.
- Ночь — мафия, ниндзя, маньяк, доктор, телохранитель: номер игрока.
- Ночь — комиссар: `п N` — проверить игрока N, `в N` — выстрелить.
- Ночь — журналист: `N M` — сравнить двух разных игроков.

Некорректный ввод ведущий отклоняет и переспрашивает. Конец ввода (Ctrl+D)
прерывает партию, код возврата 2.

## Набор ролей (YAML)

Примеры лежат в `configs/`: `classic.yaml` задаёт классический набор (как без
параметра), `extended.yaml` — набор со всеми ролями.

```yaml
roles:
  mafia: auto      # auto — floor(N/k), но не меньше 1 (k — из --mafia-k); или число
  ninja: 1         # ниндзя входит в число мафии
  commissar: 1
  doctor: 1
  maniac: 1
  journalist: 1
  bodyguard: 1
```

- Значение особой роли — `0` или `1` (допустимы и `true/false`, `yes/no`).
  Роли, которых нет в файле, в партии не участвуют.
- Мирные жители заполняют оставшиеся места; одно место всегда остаётся за мирным.
- Порядок особых ролей в файле — их приоритет. Роль, которой не хватило места,
  пропускается с сообщением, например при 5 игроках:
  `Роль «Журналист» пропущена: при 5 игроках для неё не хватило места.`
- Ниндзя занимает одно из мест мафии. Если мафиози всего один, он остаётся
  обычным, а ниндзя пропускается.
- Мафии должно быть меньше половины игроков. Иначе это ошибка, и игра не начинается.

Ошибки сообщаются с именем файла и номером строки, код возврата 1:

```
Ошибка в наборе ролей: configs/my.yaml:3: неизвестная роль «wizard»; допустимы: mafia, ninja, commissar, doctor, maniac, journalist, bodyguard
Ошибка в наборе ролей: configs/my.yaml:3: неожиданный отступ: у ключа «mafia» уже есть значение в строке 2
```

**Парсер YAML** (`yaml.hpp`) написан с нуля и поддерживает:

- блочные словари и списки (в том числе `- ключ: значение`);
- значения без кавычек, в `'…'` и `"…"` с экранированием;
- однострочные списки `[a, b]`;
- комментарии `#`, маркеры `---` и `...`, CRLF и BOM.

Табуляция в отступах, повторяющиеся ключи, якоря, теги, многострочные блоки,
`{…}` и несколько документов в файле дают понятную ошибку с номером строки.

## Правила, как они реализованы

- День 1 — знакомство: только обсуждение. Дальше циклом ночь → день (обсуждение и голосование).
- **Голосование:** выбывает набравший больше всех голосов. При равенстве ведущий
  подбрасывает монетку среди лидеров.
- **Мафия** (вместе с ниндзя) выбирает жертву вне своей команды общим решением:
  большинство предложений, при равенстве решает босс (живой мафиози с наименьшим
  номером). Стреляет первый по номеру из голосовавших за жертву — босс, если он среди них.
- **Комиссар** каждую ночь либо проверяет, либо стреляет (не в себя). Проверка
  показывает «мафия / не мафия»; маньяк и ниндзя выглядят мирными.
- **Доктор** лечит любого, включая себя, но не того же, что прошлой ночью. Лечение
  спасает от всех выстрелов этой ночи, в том числе от ответного выстрела телохранителя.
- **Маньяк** убивает каждую ночь.
- **Журналист** каждую ночь сравнивает двух других живых игроков и лично узнаёт,
  «одинаковый» у них статус или «разный» (по той же стороне, что видит комиссар).
- **Телохранитель** каждую ночь прикрывает одного игрока, кроме себя. Подопечный
  выживает при любом выстреле. Если стреляли мафия или маньяк, телохранитель
  стреляет в одного из нападавших — с наименьшим номером. От выстрела комиссара
  он просто спасает.
- **Ниндзя** — мафиози: играет за мафию, участвует в ночном решении и считается
  мафией в условиях победы и в закрытых объявлениях. Мирным его видит только
  проверка комиссара (и журналиста).
- Никто не может пропустить ход.
- **Победа** — по реальным лагерям (`Team`), проверяется после ночи и после голосования:
  - мирные — мафии и маньяка нет;
  - маньяк — мафии нет, мирных не больше одного;
  - мафия без живого маньяка — мафии не меньше, чем остальных;
  - при живом маньяке мафия побеждает при строгом численном перевесе, при
    равенстве игра продолжается до смерти мафии или маньяка;
  - все погибли или прошло 100 дней — ничья.

Лагерь и видимая сторона разделены (`roles.hpp`):

- `teamOf` — за кого игрок реально играет;
- `checkSide` — как его видят комиссар и журналист;
- `announcedSide` — что ведущий объявляет при закрытых объявлениях.

## Файловые логи

С `--log-dir DIR` ведущий пишет партию в `DIR/game_<сид>/`. Каталог создаётся
автоматически, файлы прошлой партии с тем же сидом удаляются.

- `round_01.txt`, `round_02.txt`, … Раунд k — это день k и следующая ночь k:
  - живые игроки с ролями;
  - каждая реплика с мотивом бота;
  - каждый голос и итоги голосования, кто выбыл и почему;
  - все ночные ходы;
  - итоги ночи: решение мафии, покушения, спасения доктором и телохранителем,
    ответный выстрел, проверка комиссара, сравнение журналиста, погибшие.
- `summary.txt` — сид, набор ролей, пропущенные роли, победитель, число дней,
  изгнанных и погибших, плюс таблица по каждому игроку:
  - роль, лагерь, победил ли, судьба;
  - реплики, обвинения сделанные и полученные;
  - голоса отданные, из них против мафии, и полученные;
  - ночные ходы и сколько раз игрока спасли.

Если каталог нельзя создать или запись не удалась, ведущий печатает одно
предупреждение и партия продолжается без файлов.

Логи пишет `FileLog` — реализация общего интерфейса событий `GameEventSink`
(`game_events.hpp`). Ведущий сообщает подписчикам о событиях: реплика, голос,
итоги голосования, ночной ход, итоги ночи, выбывание, конец партии. Делает он это
только из главной нити, нити игроков об этом интерфейсе не знают.

## Концепты

Концепты (`player_concepts.hpp`) описывают типы игроков и ограничивают шаблоны,
через которые идёт игра.

| Концепт | Требует | Кто удовлетворяет |
|---|---|---|
| `DayPlayer` | конкретный наследник `Player`: `id()`, `role()`, публичные `discuss()` и `vote()` → `Response` | все игроки |
| `NightPlayer` | `DayPlayer` + `act()` | ночные роли и человек, но **не** мирный житель |
| `RoleClass` | `DayPlayer` + константа `T::kRole` | все восемь классов ролей |
| `NightRole` | `RoleClass` + `NightPlayer` + статические правила хода: `nightTargets(context, self)`, `isValidNightMove(response, request)`, `fallbackNightMove(request, rng)`, `recordNightMove(moves, self, response)` | мафиози, ниндзя, комиссар, доктор, маньяк, журналист, телохранитель |
| `RoleBot` | `RoleClass` + конструктор из `(номер, сид)` | все восемь классов ролей |

Различие дня и ночи заложено в иерархию. У `BotPlayer` есть только `discuss()` и
`vote()`. Метод `act()` появляется в `NightBot`, от которого наследуются только
ночные роли. Поэтому `Civilian` — `DayPlayer`, но не `NightPlayer`.

**Шаблоны, ограниченные концептами:**

- **Ход в нити игрока** — `playTurn(player, request)`. Каждый конечный класс
  реализует `handle()` вызовом `playTurn(*this, request)`. Есть две перегрузки:
  для `DayPlayer` (ночью игрок спит) и для `NightPlayer`. Вторая уточняет первую,
  поэтому для ночных ролей компилятор выбирает её. Ночной ход `playNightTurn`
  доступен только `NightPlayer`: для мирного жителя этот вызов не компилируется.
- **Управление ночью у ведущего** — `visitNightRole` (`role_dispatch.hpp`). Ведущий
  знает роль игрока как значение `Role`. Шаблон находит класс роли в списке
  `NightRoles` и передаёт его в шаблонную лямбду `[&]<NightRole R>() {…}`. Так
  ведущий берёт из класса роли допустимые цели, проверку ответа и запасной ход.
  Ночные ходы ведущий собирает функцией `collectNightMoves`: она передаёт каждый
  ответ в `collectNightMove<R>`, которая ограничена `NightRole` (а значит, и
  `NightPlayer`). Отдельных `switch` по ролям при раздаче целей, проверке, запасном
  ходе и сборе ходов нет; в `night()` остался только `switch` для печати итогов —
  это работа ведущего.
  Список `NightRoles` — пакет `NightRole... Roles`, и мирный житель в нём не
  скомпилируется. `static_assert` проверяет, что список совпадает с ролями,
  у которых `hasNightAction` равна `true`.
- **Создание ботов** — `makeBot<T>()`, ограниченный `RoleBot`.

**Проверки:**

- `src/player_concepts.cpp`: `static_assert` для всех классов ролей, для человека
  и для базовых классов (`Player`, `BotPlayer`, `NightBot` абстрактны).
- `tests/test_concepts.cpp`: неподходящие классы концепты отвергают, а
  ограниченные шаблоны для них недоступны. Это класс-не-наследник `Player`,
  классы без `vote()`, с `vote()` другого типа, со скрытым `vote()`, абстрактный,
  без `act()`, ночной бот без правил хода, правила без `act()`, правило с
  неверной сигнатурой, класс без `kRole` и класс с другим конструктором.
  Во время выполнения тест проверяет:
  - ход мирного и ночных ролей через `playTurn`;
  - правила хода каждой роли;
  - `visitNightRole` по всем ролям;
  - что запасной ход любой ночной роли проходит её же проверку.
- Три теста CTest собирают `tests/concept_violation.cpp` скриптом
  `tests/expect_compile_failure.cmake`. Скрипт требует, чтобы сборка упала и в
  выводе компилятора встретилось имя концепта. Ищется только имя, без текста
  диагностики, поэтому проверка работает на g++ и clang в любой локали:
  - класс без `vote()` в `makeBot` → `RoleBot`;
  - ночной ход мирного жителя → `NightPlayer`;
  - мирный житель в списке ночных ролей → `NightRole`.

## Корутины (`--coroutines`)

По умолчанию каждый игрок — отдельная `std::thread`. С `--coroutines` нитей у игроков
нет: каждый игрок — корутина C++20 `Player::play()`, и все они живут в нити ведущего.
Без сторонних библиотек (`coro.hpp`):

- `Task<T>` — задача-корутина со своим `promise_type`. Она ленивая (запускается
  при `co_await` или `resume()`) и владеет кадром корутины. По завершении
  `final_suspend` симметрично передаёт управление ожидающей корутине, а
  исключения из тела пробрасываются ожидающему;
- `Scheduler` — очередь готовых к продолжению корутин; `step()` возобновляет одну;
- `CoChannel<T>` — канал: получатель засыпает на `co_await receive()`, пока пусто,
  а `push()` будит его через планировщик;
- `AsyncInput` — ввод человека: его корутина засыпает на `co_await nextLine()`.

Ведущий работает с обоими режимами через интерфейс `PlayerRuntime`
(`player_runtime.hpp`): `send` — отправить запрос, `receive` — получить ответ,
`stop` — остановить игроков. `ThreadRuntime` — прежняя схема с нитями.
`CoroutineRuntime::receive()` пошагово возобновляет готовые корутины, пока не
появится ответ.

Интерактивный игрок не блокирует остальных. Строку ввода ведущий читает только
тогда, когда продвигать больше некого: все боты к этому моменту уже ответили.
Это проверяет тест `HumanDoesNotBlockBots`: человеку запрос отправлен первым,
но ведущий получает три ответа ботов до того, как прочитана хоть одна строка.

Боты отвечают синхронно (`respondAsync` по умолчанию сразу вызывает `handle`),
человек переопределяет `respondAsync` и ждёт строку. Ходы идут через те же
`playTurn` и концепты, что и в режиме нитей. Каналы, планировщик и асинхронный
ввод хранятся в `SharedPtr`, вывод — по-прежнему только через ведущего.

Режимы дают побайтно одинаковый вывод при одном сиде, в том числе в интерактивной
игре: у каждого бота свой генератор, а ведущий разбирает ответы по порядку
номеров. Это проверяет тест `coroutines_match_threads`.

## Ranges

`std::ranges` и `std::views` используются там, где это естественно:

| Где | Что |
|---|---|
| `Moderator::aliveIds/aliveExcept/aliveInTeam` | живые игроки: `views::iota \| views::filter`; кандидаты на голосование и цели — `allExcept` |
| `tallyVotes`, `voteLeaders` (`game_rules.hpp`) | подсчёт голосов: цели — `views::values \| views::transform(&Response::target)`, `ranges::sort` и `ranges::unique`; голосовавшие против цели — `views::filter \| views::keys`; строки — `ranges::stable_sort` с проекцией; лидеры — `views::take_while` |
| `countTeams`, `decideWinner` (`game_rules.hpp`) | число мафии, мирных и маньяков — один проход `ranges::for_each` с проекцией `teamOf`, поэтому годится и однопроходный диапазон; победитель — чистая функция от этих чисел |
| `resolveNight` | голоса мафии: `ranges::count` с проекцией, `ranges::max(views::values)`, лидеры — `views::keys`; стрелявший — `ranges::find` |
| `Moderator::compositionText`, снимок `GameView` | число мафии, ниндзя, мирных — `ranges::count`/`count_if`; особые роли — `views::filter` |
| `NightContext`, правила ходов в ботах | цели ночных ходов — `views::filter`, `allExcept` |
| боты | кандидаты вне команды мафии, непроверенные игроки — `views::filter`; активность и давление на игрока — один шаблон `weightOfAccusations` (`views::filter` и `ranges::for_each` с проекцией), вес обвинения задаёт `accusationWeight` |
| человек, файловый лог | `contains` для допустимых номеров и команд; ширина строки в символах — `ranges::count_if` |

Помощники из `ranges_util.hpp` закрывают то, чего нет в C++20:

- `toVector` — собирает диапазон в вектор (`std::ranges::to` появится только в C++23);
- `contains(range, value, proj)` — есть ли значение в диапазоне (`std::ranges::contains` — тоже C++23);
- `allExcept(range, value)` — все элементы, кроме равных значению.

Все три принимают любой `input_range` и проходят его один раз.

## ИИ-агент (`--ai-agents K`)

ИИ-агент — ещё один тип игрока, `AiAgent<Bot>` (`ai_agent.hpp`), поверх
обычного бота своей роли. Днём (обсуждение и голосование) он решает с помощью
языковой модели, ночью всегда ходит вложенный бот. Подробности, пример промпта
и ответа — в [docs/AI_TRACK.md](docs/AI_TRACK.md).

```bash
export OPENROUTER_API_KEY=...   # бесплатный ключ: openrouter.ai → Keys
./build/mafia --players 9 --ai-agents 3 --full-log
./build/mafia --players 9 --roles-config configs/ai_agents.yaml
```

**Какой API.** Клиент говорит на OpenAI-совместимом протоколе Chat Completions,
поэтому подходит любой бесплатный провайдер с таким протоколом. По умолчанию —
OpenRouter и бесплатная модель `nvidia/nemotron-3-super-120b-a12b:free`.
Бесплатные модели бывают перегружены (HTTP 429) и пропадают из каталога,
поэтому к ней OpenRouter получает запасные (поле `models`):
`nvidia/nemotron-3.5-lightning:free` и `google/gemma-4-31b-it:free`. Роутер
`openrouter/free` в запасные не входит: он выбирает модель случайно и в
пробных партиях попадал на классификатор безопасности и крошечные модели,
которые не отвечают JSON. Бесплатные модели — рассуждающие, поэтому запрос к
OpenRouter ограничивает рассуждение (`reasoning: {effort: "low"}`): длинное
приводило к таймаутам и к ответам, обрезанным на рассуждении. Наблюдения из
партий с реальным API — в [docs/AI_TRACK.md](docs/AI_TRACK.md).
Другой провайдер задаётся переменными окружения:

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `OPENROUTER_API_KEY` | ключ OpenRouter (уходит только на адрес OpenRouter) | — |
| `MAFIA_LLM_API_KEY` | ключ для любого провайдера; важнее `OPENROUTER_API_KEY` | — |
| `MAFIA_LLM_BASE_URL` | адрес OpenAI-совместимого API (без `/chat/completions`) | `https://openrouter.ai/api/v1` |
| `MAFIA_LLM_MODEL` | модель (без запасных); важнее поля `model` в YAML | `nvidia/nemotron-3-super-120b-a12b:free` |
| `MAFIA_LLM_TIMEOUT_MS` | таймаут запроса | 90000 |
| `MAFIA_LLM_TRACE` | файл, куда дописываются тело каждого запроса, сырой ответ и какая модель ответила (`model_requested`, `model_answered`, `fallback_model`); JSON-строки, без ключа — для отладки | — |

```bash
# Groq (бесплатный тариф)
export MAFIA_LLM_BASE_URL=https://api.groq.com/openai/v1 MAFIA_LLM_API_KEY=gsk_... MAFIA_LLM_MODEL=openai/gpt-oss-120b
# Google Gemini (бесплатный тариф)
export MAFIA_LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai MAFIA_LLM_API_KEY=... MAFIA_LLM_MODEL=gemini-2.5-flash
# Локальная Ollama — без ключа и без интернета (ollama pull llama3.2)
export MAFIA_LLM_BASE_URL=http://localhost:11434/v1 MAFIA_LLM_MODEL=llama3.2
```

Названия бесплатных моделей у провайдеров меняются; актуальные — на их сайтах.
У бесплатных тарифов есть лимиты (у OpenRouter — около 20 запросов в минуту
к `:free`-моделям): ответ 429 агент переживает так же, как любую ошибку, —
ходит ботом.

- **Включение.** Флаг `--ai-agents K` или раздел `ai_agents` в YAML (`count`,
  `model`, `characteristics`); флаг важнее. Агентами становятся K случайных ботов,
  человек — никогда. Характеристики — список `ai_agents.characteristics` в YAML;
  в `configs/ai_agents.yaml` их десять («плохо врёт», «никому не доверяет»,
  «лидер», «миротворец», «упрямый», «шутник», …). Каждому агенту достаётся
  случайная, в одной партии они разные, пока их хватает; выбирает их тот же
  отдельный генератор, что и агентов. Без списка (только флаг `--ai-agents`) у
  всех агентов нейтральная характеристика «обычный игрок без особых привычек» —
  чтобы получить характеры, запускайте с `--roles-config configs/ai_agents.yaml`
  (там же расширенный набор ролей). Модель по умолчанию — `nvidia/nemotron-3-super-120b-a12b:free` (см. выше).
- **Промпт** — JSON только из того, что игрок мог видеть:
  - роль, лагерь, характеристика;
  - этап;
  - живые игроки и раскрытые сведения о выбывших;
  - личные сведения: свои ночные ходы, проверки, сравнения, напарники по мафии;
  - история по раундам: реплики дословно, голоса, выбывания;
  - допустимые цели.

  Системный промпт запрещает агенту-мафии обвинять напарников и голосовать
  против них из-за характеристики. Пойти против напарника можно только как
  осознанный ход ради победы мафии (например, чтобы отвести от себя подозрения),
  объяснив это в `reasoning`. Код такой ход не запрещает: напарник остаётся
  допустимой целью.
- **Ответ** — `{action, message, target, reasoning}`. Формат описан в системном
  промпте, запрос идёт в режиме JSON (`response_format: json_object`). Бесплатные
  модели ошибаются чаще, поэтому ведущий проверяет, что это JSON (блок
  `<think>…</think>` рассуждающих моделей и обёртка ```` ```json ```` отрезаются),
  что действие подходит этапу и что `target` — живой игрок из допустимых. Кроме того:
  - `message` и `reasoning` — только по-русски: латинское слово (две буквы и
    больше) делает ответ невалидным;
  - реплика совпадает с ходом: в `message` назван только игрок из `target`
    («игрок 5», «Игрока №5», «игроки 2 и 5»); назван другой — ответ невалидный.
    При `defend` и `abstain` назвать можно только себя;
  - характеристика слышна в тоне реплики, но не меняет правила игры (это
    требование системного промпта, кодом не проверяется).
- **Воздержаться (`abstain`).** На голосовании агент может не голосовать
  (`target = null`), если оснований нет, — вместо случайной цели. Ведущий
  пишет «Игрок N воздерживается — «…»», голос не считается; если воздержались
  все, днём никто не выбывает. Так может ходить только ИИ-агент.
- **Повтор.** Если ответ модели не прошёл проверку (битый JSON, мёртвая цель,
  английское слово, реплика не совпадает с целью…), агент делает один повторный
  запрос: модель видит свой ответ и пояснение, что с ним не так. Если и второй
  ответ плохой или запросов не осталось, ходит бот, а причина
  («ответ отклонён дважды: …») пишется в полный лог. Сетевые ошибки и
  таймауты не повторяются.
- **Лимит.** Не больше 10 запросов к API за раунд на всю партию, повторы
  входят в этот лимит. Квоту на каждый ход раздаёт ведущий по порядку номеров:
  сначала первые запросы всем агентам, остаток — на повторы; неиспользованное
  возвращается. Поэтому режимы нитей и корутин совпадают. Сам агент тоже не
  делает больше 10 запросов за раунд.
- **Fallback.** Агент молча ходит вложенным ботом, если:
  - нет ключа или libcurl;
  - сеть или таймаут (`MAFIA_LLM_TIMEOUT_MS`, по умолчанию 90 с);
  - HTTP-ошибка (в том числе 429 — лимит бесплатного тарифа), ошибка
    поставщика модели, отказ или фильтр контента, обрезанный ответ;
  - ответ невалиден и после повтора (или на повтор не хватило квоты);
  - исчерпана квота.

  Партия продолжается, причина видна только с `--full-log`. Без ключа партия
  с агентами идёт ровно как партия ботов — отличается только строка «ИИ-агенты: …».
- **Вывод.** Реплики и голоса агента — его словами, в консоли и в файловых
  логах. `reasoning` в консоли — только с `--full-log`; в файлах раундов — всегда,
  как и мотивы ботов. Рядом с рассуждением — модель, которая реально ответила
  (поле `model` ответа API): «ИИ (модель …): …». Если ответила запасная —
  «ИИ (ответила запасная модель … вместо …): …»; то же в причине отказа, если
  ответ модели не прошёл проверку. Строка «ИИ-агенты: … (модель …)» в начале
  партии называет запрошенную модель.
- **Без повторов.** Системный промпт просит не повторять свои прошлые реплики
  дословно и говорить каждый раз иначе (кодом не проверяется).
- **Клиент.** `LlmClient` — интерфейс (`llm_client.hpp`), в тестах вместо него мок.
  Протокол Chat Completions — чистые функции `buildChatRequest` и
  `parseChatResponse` (`llm_protocol.cpp`). Транспорт — libcurl
  (`llm_curl.cpp`): HTTPS POST `{MAFIA_LLM_BASE_URL}/chat/completions`,
  заголовок `Authorization: Bearer <ключ>` (без ключа — не отправляется,
  как нужно локальной Ollama).
- **Ограничение.** В режиме корутин запрос к API выполняется синхронно внутри
  шага корутины агента, и на время запроса планировщик ждёт.

**Нити и синхронизация.** По умолчанию каждый игрок — отдельная `std::thread`,
которая ждёт сообщения в своём входящем канале (в режиме `--coroutines` — корутина,
см. выше). Ведущий (главная нить) рассылает запросы сразу всем участникам фазы,
например всем ночным ролям. Игроки думают параллельно и отвечают в общий канал
ответов. Ведущий собирает их, проверяет и собирает ночные ходы по правилам классов
ролей (`visitNightRole`, `collectNightMoves`), вызывает `resolveNight` и применяет
итоги. Других общих изменяемых данных у игроков нет: они видят состояние только
через снимок `SharedPtr<const GameView>`, который ведущий создаёт заново на каждую
фазу. Частные сведения — результат проверки комиссара или сравнения журналиста —
приходят сообщением `Info`.

**Вывод.** Игроки (нити или корутины) ничего не печатают и не пишут в файлы: реплики, решения и
причины они возвращают в `Response`. Консоль (`Logger`) и файлы (`FileLog`) пишет
только ведущий. Подсказки человеку тоже печатает ведущий; нить `HumanPlayer`
только читает строку и разбирает её.

**Умные указатели.** Общие структуры хранятся в `SharedPtr`:

- игроки — `SharedPtr<Player>`, полученные конвертацией из `SharedPtr<Mafioso>` и т. п.;
- каналы — ими совместно владеют ведущий и нить игрока;
- снимки `GameView`, `GameState`, `Logger`;
- подписчики на события — `SharedPtr<GameEventSink>`.

`std::shared_ptr` и `std::unique_ptr` не используются.

**Боты.** `BotPlayer` по публичным событиям ведёт «подозрение» к каждому игроку:
кто кого обвинял, кто за кого голосовал, кем оказался выбывший, кого мафия
пыталась убить (в открытом режиме). Роли добавляют своё поведение:

- мафия знает напарников, давит на тех, кто обвиняет её членов, и голосует вместе с городом против мирных;
- ниндзя ведёт себя как мафиози, но смелее блефует;
- комиссар проверяет подозрительных и стреляет в найденную мафию, днём её разоблачает;
- доктор чаще лечит себя и активных обвинителей, телохранитель прикрывает активных обвинителей;
- журналист сравнивает подозрительного с надёжным. Когда сторона одного из
  сравненных раскрывается, он делает вывод о втором. Сравнение видит ниндзя
  мирным, поэтому журналист учитывает это и при выводах:
  - при открытых объявлениях роль погибшего известна, и ниндзя считается мирным;
  - при закрытых объявлениях ведущий называет ниндзя «мафией», а кем был
    погибший, неизвестно. Журналист берёт вероятность того, что погибший
    «мафиози» был ниндзя, из публично объявленного состава (`GameView::mafiaTotal`,
    `ninjaTotal`). Если ниндзя в составе нет, вывод прежний, однозначный;
- маньяк убивает самых подозрительных.

**Воспроизводимость.** У каждой нити свой генератор, полученный из сида партии
(splitmix64), а ответы ведущий обрабатывает по порядку номеров игроков. Поэтому
один и тот же `--seed` даёт побайтно одинаковый вывод независимо от планирования нитей.

## SharedPtr

`include/mafia/shared_ptr.hpp`:

- управляющий блок с `std::atomic<long>`: инкремент `relaxed`, декремент `acq_rel`;
- конструкторы: пустой, от `nullptr`, от сырого указателя, с удалителем, копирующий,
  перемещающий, конвертирующие (`Derived → Base`, `T → const T`);
- копирующее, перемещающее и конвертирующее присваивание, присваивание `nullptr`;
- `operator*`, `operator->`, `get`, `reset` (три формы), `swap`, `use_count`,
  `operator bool`, `==` и `<=>` (между указателями и с `nullptr`), `std::hash`;
- `MakeShared<T>(args...)` — объект и счётчик в одной аллокации.

Блок хранит указатель исходного типа, поэтому `SharedPtr<Base>`, созданный из
`Derived*`, вызывает `~Derived` даже без виртуального деструктора.
