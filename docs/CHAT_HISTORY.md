## Этап 1. Основная часть (6 баллов)

### 1. Основа проекта — 5 октября

> Приложено задание `2026-Task01.pdf`.
>
> Реализуй на C++20 учебный проект «Эмуляция игры Мафия» с CMake, без сторонних
> библиотек.

Требования из запроса:
- свой шаблонный `SharedPtr<T>` как `std::shared_ptr`: атомарный счётчик,
  конструкторы (в том числе из `Derived` в `Base`), копирование и перемещение,
  `operator*`, `operator->`, `reset`, `swap`, `get`, `use_count`, сравнения; тесты;
- игра: N > 4 игроков, `--interactive`, открытые или закрытые объявления, `--full-log`;
- роли: мафия (max(1, N/3)), мирный житель, комиссар, доктор, маньяк; ведущий —
  программный;
- правила из задания: комиссар проверяет или стреляет, доктор не лечит одного
  дважды подряд, маньяк стреляет каждую ночь, мафия решает сообща, днём
  голосование, победа по числу живых;
- каждый игрок — своя `std::thread`; общие структуры только в `SharedPtr`, без
  `std::shared_ptr` и `std::unique_ptr`; нити ничего не печатают, вывод только
  через ведущего;
- дополнительные пункты пока не делать;
- описать архитектуру, реализовать по шагам, прогнать партии, проверить
  ThreadSanitizer, написать README и отчёт.

**Сделано:** `SharedPtr` с тестами; ведущий, боты, игрок-человек; каждый игрок в
своей нити, общение через очереди; README; партии и ThreadSanitizer без ошибок.

### 2. Паузы — 5 октября

**Сделано:** реплики и голоса раз в 0,5 с, ночь 2 с, между фазами 1,5 с; флаг
`--no-pauses` для тестов.

## Этап 2. Дополнительные пункты: роли, YAML, файловые логи, концепты

### 3. Три новые роли, YAML, файловые логи, концепты — 6 октября

Требования из запроса:
- роли Журналист (сравнивает двух игроков, маньяк и ниндзя выглядят мирными),
  Телохранитель (прикрывает игрока и убивает одного из нападавших), Ниндзя
  (мафиози, мирный для проверки комиссара);
- разделить реальный лагерь и то, как игрока видит проверка; разрешение ночи —
  отдельной функцией;
- набор ролей из YAML через `--roles-config`, свой парсер с ошибками и номерами
  строк; роль, которой не хватило места, пропускается с сообщением;
- логи в файлы через `std::filesystem`: файл на каждый раунд и итоговая
  статистика; при ошибке записи игра продолжается; пишет только ведущий через
  общий интерфейс событий;
- концепты для типов игроков, `static_assert` и тесты с неподходящими классами;
- тесты, 100 партий под TSan и ASan, сборка без предупреждений на g++ и clang;
  без нового конфига вывод прежний.

**Сделано:** роли, `resolveNight`, YAML-парсер, `FileLog`, концепты и тесты;
вывод без конфига совпал с эталоном; санитайзеры чистые.

### 4. Замечание по концептам — 6 октября

> Концепты используются минимально. Они ограничивают только шаблон makeBot.
> NightPlayer выполняется и для Civilian, потому что он унаследовал пустой act(),
> поэтому концепт не отличает ночные роли от мирных. В задании сказано, что
> концепты должны ограничивать шаблонные функции, управляющие игровым процессом,
> например ночными ходами. Сейчас это выполнено формально. Нужно это исправить.

**Сделано:** у мирного жителя больше нет `act()`; ход выбирается перегрузками
`playTurn` по концептам; появились `NightBot`, концепты `NightRole` и `RoleBot`,
диспетчеризация `visitNightRole`.

## Этап 3. Корутины и ranges

### 5. Корутины, ranges и исправления — 10 октября

Сначала исправить замечания:
- тест `concept_rejects_role_without_vote` должен искать просто `RoleBot`
  (работать на g++ и clang в любой локали);
- `NightPlayer` не выполняется для `Civilian`; ведущий собирает ночные ходы
  шаблоном, ограниченным концептом;
- удалить `logs/` из проекта и добавить в `.gitignore`;
- параметр `--mafia-k` (по умолчанию 3, не меньше 3);
- в закрытом режиме бот-журналист считает ниндзя мирным.

Затем:
- режим `--coroutines`: каждый игрок — корутина C++20 со своим `Task` и
  `promise_type`, ведущий пошагово их запускает, человек не блокирует остальных,
  нити остаются режимом по умолчанию;
- `std::ranges`/`std::views` для живых игроков, кандидатов, подсчёта голосов и
  лагерей, определения победителя.

**Сделано:** всё перечисленное; вывод нитей и корутин совпадает побайтно.

### 6. Замечание по ranges — 10 октября

Претензии из запроса:
- `countTeams` обходит однопроходный диапазон три раза;
- ranges применены не везде: три копии `contains()` на `std::find`, ещё `find`,
  `any_of`, `count_if`; ручной подсчёт голосов в `voting()`;
- дублируется вес обвинения `a.confident ? 2.0 : 1.0`;
- мало тестов: нет отдельных тестов `toVector`, `countTeams`, `decideWinner`.

**Сделано:** `countTeams` за один проход; общие `contains`, `allExcept`, `toVector`;
`tallyVotes` и `voteLeaders`; один `accusationWeight`; тесты `test_rules`,
`test_ranges`.

## Этап 4. ИИ-агент (2 балла)

### 7. ИИ-агент — 10 октября

Требования из запроса:
- агент — новый тип игрока, включается `--ai-agents K` и/или через YAML;
  отвечает только за день, ночью ходит обычный бот;
- структурированный промпт: роль, «характеристика», живые игроки, история только
  из того, что игрок видел;
- ответ JSON `{action, message, target, reasoning}`, `target` — живой игрок;
- не больше 10 запросов к API за раунд;
- без API (нет ключа, сеть, таймаут, плохой JSON) молча играет ботом;
- интерфейс `LlmClient` для мока; реальный клиент — HTTPS через libcurl, ключ из
  окружения; без libcurl проект собирается;
- реплики и голоса — в лог и файлы, `reasoning` — только с `--full-log`;
- тесты на моке, раздел в README и `docs/AI_TRACK.md`.

**Сделано:** `AiAgent<Bot>`, `AgentBrain`, свой JSON, клиент на libcurl,
тесты на моке, документация. Сначала клиент ходил в Claude API.
